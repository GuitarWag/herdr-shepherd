# Review

## Creative decisions

A 14-second silent loop follows the password-reset example: a Codex boss receives the goal, delegates two investigations to Claude Code and Codex workers, receives findings, and prepares a plan for review. Two clitasks rows show the boss updating progress. A persistent label identifies the dialogue and timing as illustrative.

The layout stays fixed so the viewer can follow the topology. Flat green terminal panels, routed connectors, and state changes carry the story. A live terminal recording and a longer promotional film were not built; this artifact explains the workflow without inventing captured product output or promising automatic clitasks synchronization.

## Verification

HyperFrames checks runtime, layout, contrast, and deterministic motion. Full-size frames at approximately 1.4, 4.2, 7, 9.8, and 12.6 seconds and the beat/phone contact sheets were visually inspected. An independent visual review found no P0/P1 problems in the delegation and completion frames. Chrome rendered through ANGLE Metal on Apple M5.

All reading text is at least 28px in the 1080p master. There are no scene cuts, so the review produced no seam strips. The exported GIF was decoded and inspected after palette conversion, including the completion state and loop reset. It is 960×540, 14.00 seconds, 168 frames, 258,014 bytes, with infinite-loop metadata. Final checks passed with zero runtime, layout, contrast, or motion errors; 281 motion samples checked the declared assertions. No audio is present because GIF has no audio track.

## Deliberate warnings and limits

The check flags the two TODO labels reappearing for the final 0.2 seconds. This is the reset into the next loop; the same labels are held for several seconds at the beginning, so the warnings are retained intentionally.

The weakest material at phone width is the complete launch command and supporting labels. The headline, topology, and status changes remain the primary visual information; the README repeats the copyable command as text. A mobile-specific version would use sequential close-ups instead of the full topology.
